选型对比 ​

选型报告最忌讳“我觉得 qiankun 好”。可解释的结论需要统一维度、真实权重、明确取舍。

六个评估维度 ​

维度关键问题权重建议
隔离能力JS / 样式 / DOM 是否互不影响？高
接入成本子应用要改多少？构建要改多少？高
用户体验加载速度、弹窗、路由、刷新高
工程复杂度调试、部署、版本、监控中
生态与团队文档、社区、招聘、维护中
长期演进是否容易被替换、是否绑定框架中

权重按团队现状调整。强监管、多老系统的团队应提高“隔离”和“接入成本”权重。

场景化结论 ​

中后台整合 ​

首选 qiankun：生态成熟、沙箱齐全、团队熟悉度高。

备选 micro-app：子应用多为 Vite、想减少改造。

老系统渐进迁移 ​

首选 micro-app 或 wujie：子应用改造少。

保守方案 iframe：风险最低，体验可接受时优先。

强隔离要求 ​

首选 wujie 或 iframe：浏览器级 JS 隔离。

组件/模块共享 ​

首选 Module Federation：依赖可共享，构建体系成熟时收益最大。

跨框架标准组件：Web Components。

轻量调度 ​

首选 single-spa：只想要生命周期与路由，隔离自己解决。

一个可解释的评分示例 ​

假设团队情况：

  • 4 个业务团队。
  • Vue 3 与 React 混合。
  • 存在两个老系统。
  • 有统一 CI 与监控。
  • 优先保证稳定。

权重：隔离 30%、接入 25%、体验 20%、工程 15%、生态 10%。

最后一条建议 ​

选型不是选“最强的”，而是选“团队能长期维护的”。

一个团队能维护的 qiankun，胜过一个没人敢动的“完美架构”。
