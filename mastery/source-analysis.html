源码级剖析 ​

读源码的原则：先有问题，再看实现。下面按“问题 → 关键机制 → 阅读入口”组织。

single-spa ​

问题：路由变化后，应用是怎么被激活的？ ​

关键流程：

text
urlReroute()
  → getAppsToUnmount()
  → getAppsToLoad()
  → getAppsToMount()
  → 执行生命周期
1
2
3
4
5

核心文件：

  • src/applications/apps.js：应用注册表。
  • src/navigation/reroute.js：重新计算激活状态。
  • src/lifecycles/*：mount / unmount / load 的实现。

阅读建议：

  1. 先看 registerApplication 如何保存配置。
  2. 再看 reroute 如何根据 activeWhen 计算。
  3. 最后看 mount 前如何调用 loadApp。

关键概念：status ​

每个应用有状态机：

text
NOT_LOADED → LOADING_SOURCE_CODE → NOT_BOOTSTRAPPED
→ BOOTSTRAPPING → NOT_MOUNTED → MOUNTING → MOUNTED
→ UNMOUNTING → NOT_MOUNTED
1
2
3

理解了状态机，就能解释“为什么有时应用不卸载”。

qiankun ​

问题一：HTML 是怎么变成可执行脚本的？ ​

qiankun 依赖 import-html-entry：

text
importEntry(url)
  → fetch HTML
  → 提取 template / scripts / styles
  → execScripts(proxy, opts)
1
2
3
4

execScripts 会把脚本包成：

js
(function(window, self, globalThis) {
  with (window) {
    // 子应用代码
  }
})(proxy, proxy, proxy);
1
2
3
4
5

这是沙箱能生效的关键。

问题二：沙箱怎么隔离全局变量？ ​

  • SnapshotSandbox：记录与恢复 window 快照。
  • ProxySandbox：每个应用一个 Proxy，读写落在独立对象上。

阅读入口：

  • src/loader.js：加载与执行。
  • src/sandbox/：各种沙箱实现。
  • src/globalState.js：全局状态。

问题三：样式隔离怎么做的？ ​

experimentalStyleIsolation 会遍历 CSS 规则，给选择器加前缀：

css
.title { ... }
/* → */
div[data-qiankun="qk-order"] .title { ... }
1
2
3

源码在 src/sandbox/patchers/css.js。

micro-app ​

问题：为什么不需要导出生命周期？ ​

micro-app 通过自定义元素与沙箱，在子应用 HTML 加载后自动接管：

text
<micro-app> 元素 connectedCallback
  → 加载 HTML / JS / CSS
  → 创建沙箱
  → 执行脚本
  → 子应用自行 mount 到 #app
1
2
3
4
5

它不需要子应用导出 bootstrap/mount/unmount，而是通过 DOM 容器与沙箱接管生命周期。

阅读入口：

  • src/micro_app/：元素生命周期。
  • src/sandbox/：Proxy 沙箱与样式隔离。

问题：window.microApp 从哪来？ ​

micro-app 在执行子应用脚本前注入全局对象，子应用通过它 dispatch 与 addDataListener。

wujie ​

问题：iframe 里的 DOM 怎么出现在主文档？ ​

wujie 的核心是“代理 document”：

text
iframe 内执行 JS
  → 子应用 document 被 Proxy
  → DOM 操作同步到主文档的 Shadow DOM
1
2
3

关键点：

  • iframe 提供独立 window（JS 隔离）。
  • Shadow DOM 提供样式隔离与页面内嵌。
  • bus 与 props 负责通信。

阅读入口：

  • packages/wujie-core/src/index.ts：startApp。
  • packages/wujie-core/src/iframe.ts：iframe 沙箱。
  • packages/wujie-core/src/shadow.ts：Shadow DOM 渲染。

Module Federation ​

问题：import("mf_order/OrderPanel") 发生了什么？ ​

构建期：

  • host 生成远程模块映射。
  • remoteEntry.js 暴露模块清单与加载函数。

运行期：

text
import("mf_order/OrderPanel")
  → 加载 remoteEntry.js
  → 初始化共享作用域
  → 加载对应 chunk
  → 返回模块
1
2
3
4
5

shared 的作用：

  • 检查宿主是否已有依赖。
  • 复用宿主版本，避免重复加载。
  • singleton 保证只存在一个实例。

关键配置 ​

配置作用
name容器名，决定全局变量
filename远程入口文件名
exposes暴露的模块
remotes消费的远程模块
shared共享依赖与版本策略

阅读方法 ​

  1. 先跑测试：仓库的测试用例是最好的行为说明。
  2. 抓主流程：只看入口到核心路径，跳过工具函数。
  3. 做对照实验：改一个配置，观察行为变化。
  4. 画时序图：把加载、挂载、卸载画出来。
