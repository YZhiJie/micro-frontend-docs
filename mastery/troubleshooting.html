故障手册 ​

按“现象 → 可能原因 → 排查动作”组织。建议收藏，线上直接对照。

加载类 ​

子应用白屏，Network 有 HTML 但无 JS ​

可能原因排查
HTML 中脚本路径错误打开子应用 HTML，确认 src 可访问
CORS 未开启curl -I 检查 Access-Control-Allow-Origin
qiankun 子应用不是 UMD检查构建配置与产物
脚本执行报错看 Console 第一条错误

qiankun 报 application died in status LOADING_SOURCE_CODE ​

通常是入口 HTML 拉取失败或脚本执行异常：

  1. 直接访问子应用 URL，确认页面正常。
  2. 检查 preview / nginx 是否开启 CORS。
  3. 检查子应用是否引用了不存在的资源。
  4. 检查 publicPath 与 base。

micro-app 白屏 ​

  • 确认 <micro-app esmodule> 对 Vite 子应用生效。
  • 确认子应用 server.cors = true。
  • 检查 Shadow DOM 中是否有内容（DevTools 选中宿主元素）。
  • 确认子应用 #app 存在。

Module Federation 报 Failed to load remote module ​

  1. 先访问 remoteEntry.js 是否 200。
  2. 确认 remote 已构建并启动。
  3. 检查 host 配置的 URL 是否包含 /assets/。
  4. 检查共享依赖版本是否兼容。

路由类 ​

切换地址但页面不变 ​

原因：只调用了 history.pushState，没有触发路由事件。

ts
history.pushState(null, "", "/order");
window.dispatchEvent(new PopStateEvent("popstate"));

2

刷新 404 ​

  • Nginx 未配置 try_files。
  • 子应用部署在子路径，但 base 未设置。
  • 使用了 history 路由但没有服务端 fallback。

两个子应用同时显示 ​

  • activeRule 前缀重叠。
  • 容器未清理。
  • singular 配置不符合预期。

子应用内部路由丢失前缀 ​

Vue：

ts
createRouter({ history: createWebHistory("/order") });

React：

tsx
<BrowserRouter basename="/order">

样式类 ​

主应用样式影响子应用 ​

  • single-spa / Module Federation 本身无隔离。
  • qiankun 未开启 experimentalStyleIsolation。
  • 子应用写了全局选择器（body、button）。

子应用样式影响主应用 ​

  • 子应用未使用 scoped / CSS Modules。
  • 动态插入的 <style> 未被沙箱处理。
  • @keyframes 名称冲突。

Shadow DOM 内样式丢失 ​

  • 样式通过外部 <link> 引入，未进入 Shadow Root。
  • 字体、CSS 变量未显式传入。
  • 弹窗挂到了 document.body，跳出 Shadow DOM。

通信类 ​

子应用收不到 props ​

  • qiankun：检查 registerMicroApps 的 props 与子应用 mount(props)。
  • single-spa：检查 customProps。
  • micro-app：检查 setData 的应用名是否一致。
  • wujie：检查 startApp 的 props。

全局状态不同步 ​

  • 是否在 start 之前调用 initGlobalState。
  • 子应用是否调用了 onGlobalStateChange。
  • 是否修改了同一个字段但对象引用未变。

postMessage 收不到 ​

  • 目标 origin 不匹配。
  • iframe.contentWindow 尚未就绪。
  • 监听器注册在错误的 window 上。
  • 消息体被 origin 校验拦截。

生命周期类 ​

切换后定时器仍在跑 ​

unmount 未清理：

ts
export async function unmount() {
  clearInterval(timer);
  window.removeEventListener("resize", onResize);
  app?.unmount();
}

重复挂载导致 DOM 叠加 ​

  • mount 前未清空容器。
  • 子应用在 __POWERED_BY_QIANKUN__ 为真时仍自动挂载。
  • alive 配置与手动销毁冲突。

Vue 警告 “App already mounted” ​

同一个容器被挂载了两次。检查：

  • 独立运行判断。
  • 路由切换是否重复触发。
  • 是否在 mount 中重复 createApp。

性能类 ​

首屏慢 ​

  • 子应用体积过大。
  • 重复加载框架。
  • 预加载策略不当。
  • 缓存未命中。

内存持续增长 ​

  • 子应用卸载未清理。
  • alive: true 且实例越来越多。
  • 事件监听未移除。

切换卡顿 ​

  • 沙箱全量遍历 window。
  • 样式改写开销大。
  • DOM 数量过多。

部署类 ​

本地正常，线上 404 ​

  • base 与部署路径不一致。
  • 静态资源未上传。
  • CDN 缓存了旧 HTML。
  • 网关未转发子应用路径。

灰度版本串了 ​

  • remoteEntry.js 被长缓存。
  • 清单与产物版本不一致。
  • 共享依赖版本冲突。
