01 iframe：隔离基线 ​

学习目标 ​

  • 理解 iframe 为什么能天然隔离 JS、CSS、DOM。
  • 掌握 postMessage 的双向通信与 origin 校验。
  • 说清 iframe 在路由、弹窗、加载态、SEO 上的代价。

iframe 内是一个完整的浏览上下文。主应用无法直接操作其 DOM（跨域时），但可以：

  • 通过 contentWindow.postMessage 发消息。
  • 监听 message 事件收消息。
  • 同源时读取子应用的全局变量（示例中演示了这一步）。

运行 ​

bash
pnpm dev:iframe
1
  • 主应用：http://localhost:5173
  • 子应用：http://localhost:5174

页面上可以操作：

  1. 发送通知给子应用，观察子应用回执。
  2. 切换 iframe src，模拟子应用内部页面切换。
  3. 读取子应用全局变量。
  4. 开启“全局样式攻击”，观察隔离效果。

const ORDER_ORIGIN = "http://localhost:5174";

function send() {
  frame.value?.contentWindow?.postMessage(
    { type: "portal:notice", text: input.value },
    ORDER_ORIGIN,
  );
}

function onMessage(event: MessageEvent) {
  if (event.origin !== ORDER_ORIGIN) return;
  log(`[子 → 主] ${JSON.stringify(event.data)}`);
}

子应用：接收并回执 ​

[App.vue](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/micro-frontend-docs/examples/iframe/order/src/App.vue)

ts
function onMessage(event: MessageEvent) {
  if (event.origin !== "http://localhost:5173") return;
  if (event.data?.type !== "portal:notice") return;

  notice.value = event.data.text;
  (event.source as Window | null)?.postMessage(
    { type: "order:ack", text: `子应用已收到：${notice.value}` },
    event.origin,
  );
}

iframe 重新加载会丢失内部状态，这也是 iframe 方案体验差的根源之一。

验证清单 ​

  • [ ] 主应用能收到子应用的 order:ack。
  • [ ] 子应用能显示主应用发来的通知。
  • [ ] 切换 page 后 iframe 内容变化。
  • [ ] 开启样式攻击后，子应用样式不变。
  • [ ] 跨域读取 __ORDER_STATE__ 被拦截。

坑点 ​

1. 弹窗被 iframe 裁切 ​

子应用内的 alert 或自定义弹窗只能在 iframe 区域内显示。解决方式：

  • 子应用通过 postMessage 请求主应用弹出全局弹窗。
  • 或把弹窗库配置为挂载到 window.parent.document（跨域不可行）。

2. 高度自适应 ​

iframe 不会自动撑高。需要子应用上报内容高度：

ts
window.parent.postMessage(
  { type: "order:height", height: document.body.scrollHeight },
  "http://localhost:5173",
);

主应用监听后设置 frame.style.height。

3. 路由不同步 ​

主应用地址栏不会随 iframe 内部路由变化。用户刷新页面会回到初始状态。需要：

  • 子应用把路由变化上报给主应用，主应用更新地址栏。
  • 或接受“iframe 内路由不参与主应用 URL”。

4. 登录态与 Cookie ​

同域 iframe 可共享 Cookie；跨域时受 SameSite 限制，可能出现登录态丢失。

5. 性能 ​

每个 iframe 都有独立文档与 JS 运行时。多个 iframe 同时存在会显著增加内存。

iframe 是理解“隔离成本”的基线。当你觉得 qiankun 的沙箱问题时，回来看看 iframe 就明白：隔离从来不是免费的。

练习 ​

  1. 给子应用增加“详情页”，并通过 postMessage 让主应用同步地址栏。
  2. 让子应用上报高度，主应用自动调整 iframe 高度。
  3. 把 postMessage 的目标 origin 改成 "*"，观察安全隐患。
  4. 用两个 iframe 同时加载订单与商品，比较内存占用。
