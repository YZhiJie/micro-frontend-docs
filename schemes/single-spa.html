03 single-spa ​

学习目标 ​

  • 理解 bootstrap / mount / unmount 生命周期。
  • 用 registerApplication 按路由调度子应用。
  • 看清 single-spa 不提供的部分：沙箱、样式隔离、HTML Entry。

single-spa 只做三件事：

  1. 加载子应用入口。
  2. 按 URL 决定激活哪个应用。
  3. 调用生命周期。

运行 ​

bash
pnpm dev:single-spa
1
  • 主应用：http://localhost:5177
  • 订单（Vue）：http://localhost:5178
  • 商品（React）：http://localhost:5179

打开主应用后，在“订单应用 / 商品应用”之间切换，观察控制台的生命周期日志。

验证清单 ​

  • [ ] 主应用默认跳转到 /order，订单应用出现。
  • [ ] 切换到 /product 后，订单应用卸载、商品应用挂载。
  • [ ] 控制台能看到 bootstrap / mount / unmount 日志。
  • [ ] 直接访问 5178 / 5179，子应用能独立运行。
  • [ ] 两个子应用的 h2 样式互相覆盖（说明无样式隔离）。

坑点 ​

1. 没有样式隔离 ​

两个子应用都写了：

css
h2 { color: ...; }
1

后加载的样式会覆盖先加载的。示例刻意保留这个问题，方便观察。

解决方式：

  • 子应用使用 CSS Modules / scoped。
  • 自行引入 Shadow DOM 包装。
  • 或者换用 qiankun / micro-app。

2. 没有 JS 沙箱 ​

两个应用共享 window。任何全局变量、原型链修改都会互相影响。

3. 容器要预先存在 ​

mount 时容器必须已经在 DOM 中。主应用需要始终渲染两个容器，用 v-show 控制显示，而不是 v-if。

4. 远程入口的 CORS ​

子应用 dev server 需要：

ts
server: { cors: true }
1

否则动态 import 会被浏览器拦截。

5. 生命周期必须成对 ​

mount 中创建的资源（定时器、事件监听、Vue app）必须在 unmount 中释放，否则切换多次后会泄漏。

与其它方案的差异 ​

维度single-spaqiankunmicro-app
加载单位入口 JSHTML Entry自定义标签
沙箱无有有
样式隔离无可选Shadow DOM
接入改造导出生命周期导出生命周期 + UMD几乎不改
灵活度最高中中

single-spa 是“骨架”，qiankun 是“骨架 + 隔离 + 加载器”。理解 single-spa 后，qiankun 的行为会变得可预测。

练习 ​

  1. 给商品应用增加一个 React 内部路由，验证主应用切换时状态是否保留。
  2. 在 unmount 中故意不清理定时器，观察切换多次后的日志。
  3. 把 activeWhen 改成精确匹配 /order，观察 /order/list 是否还能激活。
  4. 用 single-spa 加载一个原生 JS 子应用（只需导出生命周期）。
