05 micro-app ​

学习目标 ​

  • 用 <micro-app> 标签接入子应用，理解“类 Web Component”的设计。
  • 让 Vite 子应用以 esmodule 模式运行。
  • 用 window.microApp 完成双向数据通信。

原理图 ​

text
主应用（localhost:5183）
┌──────────────────────────────────────────────┐
│ <micro-app name="order" url="...5184" esmodule> │
│   ┌───────────── Shadow DOM ─────────────┐   │
│   │ 子应用 DOM + 子应用样式                │   │
│   └──────────────────────────────────────┘   │
│   window.microApp ↕ 数据通道                 │
└──────────────────────────────────────────────┘

micro-app 的关键设计：

  • 子应用不需要导出生命周期。
  • 子应用原则上不需要改构建，但 Vite 子应用要把资源 base 配成绝对地址。
  • 容器是自定义元素，内部用 Shadow DOM 隔离样式。

运行 ​

bash
pnpm dev:micro-app
1
  • 主应用：http://localhost:5183
  • 订单（Vue）：http://localhost:5184
  • 商品（React）：http://localhost:5185

两个子应用会同时加载，用页签切换显示。可以在主应用输入公告后点击“setData 广播”。

启动脚本会先构建两个子应用，再用 vite preview 提供服务，主应用保持 dev 模式。原因见下方“Vite 子应用要加 esmodule 与绝对 base”。

坑点 ​

1. Vite 子应用要加 esmodule 与绝对 base ​

Vite 输出的是 ES Module。micro-app 需要显式声明：

html
<micro-app name="order" url="..." esmodule></micro-app>
1

漏掉 esmodule 后可能出现脚本未执行、白屏或资源 404。

更重要的是：micro-app 会把子应用 HTML 注入主文档，HTML 里的 /assets/index.js 会按主应用 origin 解析。因此子应用构建时必须使用绝对地址：

ts
export default defineConfig({
  base: "http://localhost:5184/",
});
1
2
3

本示例先构建子应用、再用 preview 提供服务，这样 HTML 里引用的就是带子应用域名的绝对 URL。若坚持用 dev server，同样需要把 base 配成完整地址，并确认 Vite 注入的客户端脚本也指向子应用。

2. 子应用也需要 CORS ​

ts
server: { cors: true }
1

主应用要跨域拉取 HTML 与静态资源。

3. Shadow DOM 的弹窗问题 ​

子应用内的弹窗如果挂到 document.body，会跳出 Shadow DOM，可能丢失样式。解决：

  • 弹窗挂到子应用自己的根节点。
  • 或使用 micro-app 提供的弹窗容器方案。
  • 或统一由主应用提供 Toast / Modal 服务。

4. 路由前缀 ​

使用 micro-app 的路由能力时，需要配置 baseroute：

html
<micro-app name="order" url="..." baseroute="/order" router-mode="native"></micro-app>
1

子应用内读取 window.__MICRO_APP_BASE_ROUTE__ 作为 baseroute。

5. 同时加载多个子应用 ​

两个 <micro-app> 同时存在会同时加载资源。示例为了让两个应用都收到广播而这样做了。生产环境如果只需当前页签，可配合懒加载或 destroy。

6. 生命周期差异 ​

micro-app 不需要导出 bootstrap/mount/unmount，但提供了 window.microApp 上的事件与数据 API。调试时要区分“子应用自己的生命周期”和“micro-app 的生命周期”。

与其它方案的差异 ​

维度micro-appqiankunwujie
接入方式自定义标签HTML EntrystartApp
子应用改造最少生命周期 + UMD最少
样式隔离Shadow DOM前缀改写Shadow DOM
JS 隔离ProxySnapshot / Proxyiframe
通信microApp 数据通道全局状态bus

micro-app 的取舍是：用标签降低接入成本，用 Shadow DOM 做样式隔离，用 Proxy 做 JS 隔离。

练习 ​

  1. 关闭 esmodule，观察子应用是否还能加载。
  2. 在子应用内引入一个全局样式库，验证 Shadow DOM 是否隔离。
  3. 用 baseroute 给订单应用加一个内部路由。
  4. 在主应用监听 microApp.addGlobalDataListener，实现全局广播。
