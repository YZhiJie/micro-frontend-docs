04 qiankun ​

学习目标 ​

  • 用 HTML Entry 接入 UMD 子应用。
  • 理解 experimentalStyleIsolation 的作用与边界。
  • 用 initGlobalState 做主应用与子应用的状态同步。

text

qiankun = single-spa + HTML Entry + 沙箱 + 样式隔离 + 全局状态。

运行 ​

bash
pnpm dev:qiankun
1

这条命令会：

  1. 构建订单与商品子应用（UMD）。
  2. 启动主应用 dev（5180）。
  3. 启动子应用 preview（5181 / 5182）。

单独构建：

bash
pnpm build:qiankun
1

  const target = props.container?.querySelector("#app");

验证清单 ​

  • [ ] 访问 /order 与 /product，能切换子应用。
  • [ ] 切换时能看到 beforeMount / afterMount / afterUnmount 日志。
  • [ ] 主应用修改公告，两个子应用都能看到。
  • [ ] 子应用点击“通知基座”，主应用日志出现新状态。
  • [ ] 两个子应用的全局 h2 样式互不覆盖。
  • [ ] 子应用 preview 返回 Access-Control-Allow-Origin。

坑点 ​

1. Vite 子应用不能直接跑 dev ​

qiankun 通过 eval 执行脚本，ES Module 的 import 语句会失败。必须：

  • 构建 UMD。
  • HTML 引用构建产物。
  • 用 vite preview 或静态服务器提供 dist。

2. CORS 必须开启 ​

vite preview 也要配置：

ts
preview: { cors: true }
1

否则 HTML 拉取成功，脚本被拦截。

3. 样式隔离不是万能的 ​

experimentalStyleIsolation 会改写选择器，但：

  • body、html 上的规则可能仍然影响全局。
  • 动态插入的 <style> 可能漏改写。
  • @keyframes 名称冲突仍可能发生。

关键样式仍建议加命名空间。

4. singular 与多实例 ​

singular: false 允许同时挂载多个子应用。如果同一时间只允许一个，保持默认 true 更容易排查。

5. 独立运行判断 ​

子应用在独立访问时必须自己挂载：

ts
if (!(window as any).__POWERED_BY_QIANKUN__) {
  render();
}
1
2
3

忘了这一步，直接访问子应用会白屏。

6. 容器选择器 ​

container: "#subapp" 必须真实存在。qiankun 会把子应用 HTML 插入该容器，卸载时移除。

与其它方案的差异 ​

维度qiankunsingle-spamicro-app
加载HTML Entry入口 JS自定义标签
沙箱Snapshot / Proxy无Proxy
样式隔离前缀改写 / Shadow DOM无Shadow DOM
子应用改造生命周期 + UMD生命周期几乎不改
全局状态initGlobalState自行实现setData

练习 ​

  1. 把 experimentalStyleIsolation 关闭，观察样式冲突。
  2. 给商品应用增加 update 生命周期，验证 props 更新。
  3. 用 prefetch: true 开启预加载，观察网络面板。
  4. 把子应用部署到不同路径，配置 base 并修正 HTML 资源路径。
