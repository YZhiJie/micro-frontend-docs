02 Web Components ​

学习目标 ​

  • 用 defineCustomElement 把 Vue 组件变成原生自定义元素。
  • 理解 Shadow DOM 的样式隔离边界。
  • 掌握 attribute / property / CustomEvent 的跨框架通信方式。

Web Components 是浏览器标准，与框架无关。Vue、React、原生 JS 都能消费同一个自定义元素。

运行 ​

bash
pnpm dev:web-components
1
  • 主应用：http://localhost:5175
  • 子应用（独立运行）：http://localhost:5176

主应用会动态注入子应用构建后的 ES Module：

ts
const script = document.createElement("script");
script.type = "module";
script.src = "http://localhost:5176/wc-order.js";
document.head.appendChild(script);
1
2
3
4

pnpm dev:web-components 会先构建子应用为固定文件名的单文件 ESM（wc-order.js），再用 vite preview 提供服务，主应用保持 dev 模式。这样做的原因是：主应用按绝对 URL 加载模块，如果直接加载子应用 dev server 的源码，模块内的相对导入会按主应用 origin 解析，容易 404 或加载到错误的依赖。

因此子应用服务必须开启 CORS。

坑点 ​

1. 样式隔离是双向的 ​

Shadow DOM 阻止外部样式进入，也意味着主应用的主题变量无法直接生效。需要显式设计：

css
/* 通过 CSS 变量穿透 */
order-widget {
  --order-primary: #2563eb;
}
1
2
3
4

组件内部使用 var(--order-primary)。

2. 继承属性仍会穿透 ​

color、font-family、font-size 等可继承属性会从宿主传入。如果子应用未显式设置，可能受到主应用影响。

3. 事件默认不跨 Shadow 边界 ​

普通事件在 Shadow DOM 边界会被重定向。需要 composed: true 才能冒泡到外部：

ts
this.dispatchEvent(
  new CustomEvent("order:select", { detail, bubbles: true, composed: true }),
);
1
2
3

Vue 的 emit 在自定义元素中默认行为需要验证，复杂场景建议手动派发。

4. 开发态跨域加载 ​

主应用加载构建后的单文件 ESM 时，子应用只要开启 CORS 即可。如果直接加载子应用的 dev server 源码，模块内的相对导入会按主应用 origin 解析，通常需要把子应用 base 配成绝对地址，否则会出现 /src/xxx.vue 404。生产环境应加载构建产物，而不是源码路径。

5. SSR 不友好 ​

自定义元素依赖浏览器 API。SSR 场景需要 client-only 或动态加载。

6. Vue 运行时重复 ​

子应用打包了自己的 Vue 运行时。如果主应用也是 Vue，会存在两份 Vue。组件级共享时，考虑 external 或 Module Federation 共享。

与其它方案的差异 ​

维度Web ComponentsqiankunModule Federation

Web Components 更像“跨框架组件协议”，不负责应用级调度。做整页微前端时，它通常作为补充手段。

练习 ​

  1. 给 <order-widget> 增加 theme 属性，并通过 CSS 变量控制主色。
  2. 用原生 JS 写一个页面，消费同一个自定义元素。
  3. 把组件内的 mf-select 改为 composed: true，观察主应用监听差异。
  4. 尝试在主应用 CSS 中写 order-widget button { ... }，验证是否生效。
