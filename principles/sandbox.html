JS 沙箱 ​

微前端最危险的问题不是样式错乱，而是全局变量被覆盖。例如两个子应用都往 window 上挂 utils，后加载的会覆盖前者。

JS 沙箱的目标：让子应用以为自己独占 window，退出时恢复原状。

沙箱需要拦截什么 ​

资源例子不拦截的后果
全局变量window.foo = 1互相覆盖
原型链Array.prototype.xxx污染所有应用
定时器setInterval卸载后仍在跑
事件监听window.addEventListener泄漏、重复触发
DOM 查询document.querySelector查到别的应用节点
动态脚本document.createElement('script')绕过沙箱执行

三种主流实现 ​

1. 快照沙箱（Snapshot Sandbox） ​

思路：应用挂载前给 window 拍快照，卸载后对比差异并恢复。

js
class SnapshotSandbox {
  constructor() {
    this.snapshot = {};
    this.modifiedKeys = [];
  }

  activate() {
    // 记录当前 window 的所有属性
    for (const key in window) this.snapshot[key] = window[key];
    // 还原上一次该应用留下的属性
    Object.keys(this.modified).forEach((key) => {
      window[key] = this.modified[key];
    });
  }

  inactive() {
    this.modified = {};
    for (const key in window) {
      if (window[key] !== this.snapshot[key]) {
        this.modified[key] = window[key];
      }
    }
    // 恢复到快照
    for (const key in this.snapshot) window[key] = this.snapshot[key];
  }
}

2. Proxy 沙箱（Proxy Sandbox） ​

思路：给每个子应用创建一个 window 代理对象，所有全局读写都落到代理上。

js
function createProxySandbox() {
  const fakeWindow = Object.create(null);
  const proxy = new Proxy(fakeWindow, {
    get(target, key) {
      if (key in target) return target[key];
      return window[key];
    },
    set(target, key, value) {
      target[key] = value;
      return true;
    },
    has(target, key) {
      return key in target || key in window;
    },
  });
  return proxy;
}

3. iframe 沙箱 ​

思路：把子应用放进一个隐藏 iframe 执行，天然拥有独立的 window。

wujie 的做法：

  • JS 在 iframe 中执行，享受浏览器级隔离。
  • 通过 Proxy 把 iframe 的 document 指向主文档的 Shadow DOM。
  • 渲染结果出现在主页面布局中。

优点：

  • 隔离最彻底，原型链、定时器、事件全部独立。
  • 子应用几乎不需要改造。

缺点：

  • 多一个文档上下文，内存与调试成本更高。
  • 跨 iframe 通信需要桥接（wujie 已封装）。
  • 某些依赖 window.top 的库可能行为异常。

沙箱的边界 ​

即使是最强的 iframe 沙箱，也不能解决所有问题：

  • 网络请求：子应用仍可能请求主应用的接口，需要网关鉴权。
  • 存储：localStorage 按域共享，可能互相覆盖 key。
  • CSS：JS 沙箱不处理样式，需要额外的样式隔离。
  • 弹窗：document.body.appendChild 的弹窗可能挂到主文档，需要 portal 约定。

工程建议 ​

  1. 子应用尽量不修改全局，把工具挂到模块内。
  2. 必须挂全局时，加命名空间，例如 window.__ORDER_APP__。
  3. 定时器与事件监听在卸载时清理。
  4. 不要依赖 window.top === window 这类判断。
  5. 用 import.meta.env 或注入的 props 区分独立运行与嵌入运行。
