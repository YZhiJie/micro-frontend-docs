HTML Entry ​

single-spa 要求主应用知道子应用的入口 JS。qiankun 换了个思路：

子应用只需要提供一个 HTML URL，主应用自己去解析、加载、执行。

这就是 HTML Entry。它让接入成本大幅降低，也带来了一系列构建与跨域问题。

基本流程 ​

text
1. fetch 子应用 HTML
2. 解析出 <script> 与 <link rel="stylesheet">
3. 把 HTML 转成模板字符串
4. 依次加载脚本，注入沙箱执行
5. 把模板插入容器，执行 mount
6. 卸载时移除 DOM、清理沙箱

qiankun 底层使用 import-html-entry：

js
import { importEntry } from "import-html-entry";

const { template, execScripts, assetPublicPath } = await importEntry(
  "http://localhost:5181",
);

// 在沙箱里执行脚本，拿到生命周期
const scripts = await execScripts(globalProxy, {
  beforeExec: (code, scriptSrc) => {
    // 可在这里做代码改写
    return code;
  },
});

子应用需要满足什么 ​

1. HTML 可被跨域 fetch ​

主应用与子应用通常不同源，必须开启 CORS：

ts
// vite.config.ts
export default defineConfig({
  server: { cors: true },
  preview: { cors: true },
});

否则浏览器会拦截 HTML 与脚本的读取。

2. 脚本要能被解析执行 ​

qiankun 通过 eval 或 new Function 执行脚本。ES Module 的 import 语句在这种环境下无法直接运行，因此子应用需要构建成 UMD。

示例项目的 qiankun 子应用配置：

ts
// examples/qiankun/order/vite.config.ts
export default defineConfig({
  build: {
    lib: {
      entry: "src/main.ts",
      name: "qkOrder",
      formats: ["umd"],
      fileName: () => "qk-order.js",
    },
    rollupOptions: {
      output: {
        assetFileNames: "qk-order.[ext]",
        inlineDynamicImports: true,
      },
    },
  },
});

为什么 Vite dev server 不能直接给 qiankun 用 ​

Vite dev 输出的是原生 ES Module：

html
<script type="module" src="/src/main.ts"></script>
1
  • type="module" 的脚本不能通过 eval 执行。
  • 模块内部的静态 import 需要浏览器模块加载器。
  • 开发态还有 HMR 客户端注入。

因此示例采用：

bash
pnpm build:qiankun   # 先构建 UMD
pnpm dev:qiankun     # 再同时启动主应用 dev 与子应用 preview
1
2

子应用用 vite preview 提供构建产物，主应用仍可用 Vite dev。

资源路径与 publicPath ​

HTML Entry 会计算 assetPublicPath，用于补全相对路径。常见问题：

现象原因解决
JS 404HTML 中写死相对路径，基座路径不同用绝对路径或配置 base
CSS 未加载样式通过 JS 动态插入，未走 <link>改为构建产物 CSS
图片 404资源路径基于主应用解析设置 publicPath 或使用完整 URL

部署到子路径时，确保子应用的 base 与访问地址一致。

脚本执行与沙箱 ​

execScripts 会把代码包裹后执行：

js
(function (window, self, globalThis) {
  with (window) {
    // 子应用代码
  }
})(proxyWindow, proxyWindow, proxyWindow);
1
2
3
4
5

这让子应用中的 window、self、globalThis 都指向沙箱代理。

需要注意：

  • 通过 document.createElement("script") 动态插入的脚本可能绕过沙箱。
  • Web Worker、Service Worker 不受沙箱影响。
  • eval 在某些 CSP 配置下会被禁用。

排查清单 ​

接入 qiankun 时，按顺序检查：

  1. 子应用 HTML 能否在浏览器直接打开？
  2. curl -I 是否返回 Access-Control-Allow-Origin？
  3. HTML 中的 JS/CSS 路径是否 200？
  4. JS 是否为 UMD，且生命周期导出正确？
  5. 子应用是否在 __POWERED_BY_QIANKUN__ 为真时跳过自动挂载？
