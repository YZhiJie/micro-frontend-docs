通信机制 ​

微前端的通信设计，核心不是“怎么传”，而是“谁应该知道谁”。

耦合度从低到高：

3. 事件总线：解耦的发布订阅 ​

wujie 提供 bus：

js
// 主应用
import { bus } from "wujie";
bus.$emit("portal:notice", { text: "系统升级" });
bus.$on("order:select", (data) => console.log(data));

// 子应用
window.$wujie.bus.$emit("order:select", { id: "SO-1001" });
window.$wujie.bus.$on("portal:notice", (data) => {});

4. postMessage：跨浏览上下文 ​

iframe 场景下唯一可靠的通信方式：

js
// 主 → 子
frame.contentWindow.postMessage(
  { type: "portal:notice", text: "系统升级" },
  "http://localhost:5174",
);

// 子 → 主
window.parent.postMessage(
  { type: "order:ack", text: "已收到" },
  "http://localhost:5173",
);

安全要点：

  1. 必须校验 origin，否则任意页面都能发消息。
  2. 发送时指定目标 origin，不要用 "*"。
  3. 消息体加 type 字段，避免误处理。
  4. 不要通过 postMessage 传递敏感凭据。

5. 共享模块（Module Federation） ​

Module Federation 的方式是直接共享代码：

js
const { userStore } = await import("mf_shared/store");
1

这不是通信机制，而是共享依赖。使用时要注意：

  • 共享模块的 API 是强契约，改动需要版本管理。
  • 不要把可变单例当作“全局状态”滥用。
  • 共享包也要走发布流程。

怎么选 ​

需求推荐原因
主应用向子应用传配置props显式、单向
多应用共享用户/主题全局状态主应用可控
应用间通知事件事件总线 / CustomEvent解耦
iframe 通信postMessage唯一通道
共享工具与类型共享包 / Module Federation避免重复实现
大量实时数据同步重新划分边界说明不该拆

通信设计的三条原则 ​

  1. 优先单向数据流：主应用下发，子应用上报。
  2. 契约先行：事件名、状态字段、消息类型都写进文档。
  3. 可观测：关键通信打日志（示例项目都提供了日志面板）。
